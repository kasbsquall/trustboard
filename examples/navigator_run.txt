Two real runs of the Navigator, recorded verbatim on 2026-07-30 against a local
DataHub. Nothing in scripts/navigator_demo.py names a dataset. The searches, the
trust checks, the substitution and the refusal are the agent's, not the author's.


=== RUN 1: the agent has to find the right words ===

Task: Build the executive revenue dashboard for the quarterly board pack

  find_datasets 'revenue'                          -> 8 matches
  find_datasets 'quarterly board revenue summary'  -> 0
  find_datasets 'finance revenue summary'          -> 0
  find_datasets 'sales revenue fact table'         -> 0
  find_datasets 'executive KPI dashboard'          -> 0
  find_datasets 'orders'                           -> 8 matches
  find_datasets 'essential KPI measures'           -> 1 match
  check_trust   Essential_KPI_Measures             -> rated, silver, trustworthy
  check_trust   analytics.order_history            -> rated, gold, trustworthy
  submit_plan

Chose: dbt ORDER_ENTRY_DB.analytics.order_history

  "Selected order_history (dbt, Data Platform Team): gold-tier, trust score 92.21,
   and provides the incremental historical order data needed to compute revenue for
   the board pack. Considered the Marketing-owned Essential KPI Measures PowerBI
   dataset as an alternative; it passed the silver trust bar but had a much lower
   owning-team trust score and less direct revenue lineage."

Five of the seven searches returned nothing. The catalog does not use the words
the task used, so the agent kept rephrasing until it did. It then declined an
asset it was ALLOWED to take, on the strength of the owning team's score.


=== RUN 2: the best candidate is at-risk, so it finds another one ===

Task: Build a regional sales breakdown by product category for the sales team,
      using the regions and product category reference tables

  find_datasets 'regions reference table'          -> 3 matches
  find_datasets 'product category reference table' -> 0
  find_datasets 'sales by region'                  -> 1 match
  find_datasets 'product category'                 -> 8 matches
  find_datasets 'products'                         -> 8 matches
  check_trust   dbt regions                        -> rated, gold
  check_trust   dbt product_categories             -> rated, AT-RISK, NOT trustworthy
  check_trust   dbt analytics.order_details        -> rated, gold
  check_trust   snowflake product_categories       -> rated, gold
  check_trust   postgres product_categories        -> rated, gold
  check_trust   s3 product_categories              -> rated, silver
  record_refusal dbt product_categories            -> written to the graph
  submit_plan

Chose: snowflake order_entry_db.order_entry.product_categories

  "Use dbt `regions` (gold, 98.46) as the region reference table, Snowflake
   `PRODUCT_CATEGORIES` (gold, 92.21) as the product category reference table, and
   dbt `order_details` (gold, 98.46) as the sales fact table joining them. The
   dbt-modeled `product_categories` table was rejected because it rated at-risk
   (39.75, below the silver bar); the equivalent Snowflake source table for the
   same entity is gold-rated and serves the task instead."

This is the whole argument in one run. The obvious candidate failed the trust
check, so the agent went looking for the same entity on other platforms, found
four of them, compared their scores, and substituted. Then it wrote the refusal
back onto the rejected dataset.
